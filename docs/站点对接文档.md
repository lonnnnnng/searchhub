## 架构与基础能力

```
App
 ├─ MainActivity → AppRoot(CaptchaHost) → SearchHubNavHost
 ├─ SearchScreen(搜索+tab) / DetailScreen(资源列表) / SettingsScreen(站点配置)
 ├─ AppViewModel(engine/repository/配置/captcha事件)
 └─ data 层
     ├─ HttpEngine       网络层(UA/cookie/各类请求)
     ├─ SearchRepository 并发聚合 + 适配器分发
     ├─ SiteAdapter      适配器接口
     ├─ ConfigStore      站点配置持久化(增量合并)
     └─ XxxAdapter       每站一个
```

### SiteAdapter 接口

```kotlin
interface SiteAdapter {
    val id: String
    val displayName: String
    val config: SiteConfig
    suspend fun search(kw: String, page: Int = 1): List<SearchResult>
    suspend fun detail(detailUrl: String): DetailInfo
}
```

### HttpEngine 能力矩阵（data/HttpEngine.kt）

| 方法 | 场景 | 说明 |
|---|---|---|
| `getText(url, referer)` | 常规 SSR | UTF-8 解码 |
| `getTextGbk(url, referer)` | 帝国CMS老电影站 | GBK 解码 |
| `getBytes(url, referer)` | 验证码图片 | 原生字节（**必须走共享 cookie/UA**，见 App 层坑 3） |
| `postText` / `postTextGbk` | 帝国CMS POST 搜索 | 表单 |
| `postJson(url, body, referer)` | 451024 / Showpaw | JSON body |
| `post(url, form, referer)` | binhd csrf POST | 跟随 303 返回最终 URL |

关键实现点：
- **UA** 固定 `Mozilla/5.0 (Linux; Android 13; Pixel 7) ... Chrome/120.0 Mobile`（多数站对无 UA 返回 403/空）。
- **cookie**：`PersistentCookieJar` 按 host 存，用于验证码 session（雪落 JSESSIONID）、csrf（binhd）、下载配额。

### ConfigStore 增量合并（data/ConfigStore.kt）

- 站点列表存 `files/config.json`。
- `load()` 合并规则（修复迭代后确定）：
  1. 读取已保存站点；
  2. 只保留 `id` 仍存在于 `SiteDefaults.DEFAULT_SITES` 的（**自动过滤已移除的站**，如 hkbdy）；
  3. defaults 有但本地没有的新站自动补上（新增站点后升级 App 即生效，无需清数据）。
- 坑：早期实现直接 `sites += defaults 中缺失的`，导致**已删除站点（hkbdy）仍保留**在旧 config 里 → 改成先 filter 再 merge。

## 接入总流程（新增站点 How-To）

1. **探测可达性**：`curl -A "Mozilla..." -o /dev/null -w "%{http_code}" https://host/`。确认非 CF 拦截、非 403、非付费墙。
2. **确定搜索入口**：
   - 直接找 `<form>`（帝国CMS→POST `/e/search/index.php`，Z-Blog→`?q=`，WordPress→`/?s=`）；
   - 或找热词链接推断路径（如 kuaisouxia `/s/{kw}.html`）；
   - SPA 用 js-reverse 抓 XHR（如 451024 的 `apis.*/api/media/search`、Showpaw `/api/search`）。
3. **编码确认**：响应头 charset 或试 `gbk`/`utf-8` 解码；老站（帝国CMS/6v/xb6v）多为 GBK，部分（xb6v 实为 UTF-8）特殊。
4. **写 Adapter**（实现 `SiteAdapter`）：search 解析列表，detail 解析资源。
5. **接入三处**：`SearchRepository.rebuild()` 加分支、`SiteDefaults` 加默认配置、如有特殊资源跳转在 `resolveResource()` 加分支。
6. **本地验证解析**：把真实 HTML 存盘 + 用 `jsoup-1.18.3.jar` 写 JVM 测试复现 `search()` 选择器，确认条数/标题正确（比反复装 APK 快得多）。
7. **真机验证**：装 APK → 搜关键词 → 检查 tab 条数 → 进详情看资源类型。
8. **无法对接的站点**：记录跳过原因，不阻塞其它站。

## 逐站详细对接记录

### 1. BT影视 btbtlb.com

- **ID**：`btbtlb` / 显示名 `BT影视` / 适配器 `BtbtlbAdapter.kt`
- **搜索**：`GET /search/{kw}`，分页 `/search/{kw}/{page}`。纯 SSR。
- **结果**：`.module[class*=module-item]` → `a[href*=/detail/]`，标题 `attr("title")`，年份从整块文本正则 `(19\d{2}|20\d{2})` 提取；海报取 `img` 的 `data-src`（懒加载属性而非 `src`）。
- **详情**：`/detail/{id}.html` → `a[href*=/tdown/]` 每个资源；`title` 属性即资源文件名。
- **资源二次跳转（关键）**：`tdown/{id}.html` 页面直接含：
  - `a[href^=magnet:]` → **磁力链接**
  - `a[href*=/dlt/]` → **种子文件直链**
  - `resolveTdown(engine, fetchUrl)` 抓 tdown 页提取两者，magnet 优先。
- **过程/尝试**：
  - 首页表单写死 `onsubmit` 跳 `/search/{kw}`，一开始误用 `/vsearch` → 404，改看内联 JS 才找到真实路径。
  - 详情页正文没有 `magnet:` 明文（一开始怀疑异步加载），实际磁力藏在每个 tdown 页里，需要二次请求。
- **资源类型**：磁力 / 种子。
- **真机验证**：batman→8条；某详情 214 个资源项；点击「解析链接」后首个资源从"种子"变"磁力"，出现复制/打开按钮 ✅。

### 2. 狐狸君 foxjun.com

- **ID**：`foxjun` / 显示名 `狐狸君` / 适配器 `FoxjunAdapter.kt`
- **搜索**：**JSON API**（不是 SSR！虽然 URL 是 `/search?q=`）：
  - 页面 SSR 只给"正在搜索…"骨架，真实结果由 JS 调 API 渲染。
  - 用 js-reverse 抓 XHR 发现：`GET https://api.foxjun.com/v1/search?q={kw}&page={n}`。
  - **坑：API 在 `api.` 子域**。适配器用 baseUrl 推导：
    ```kotlin
    val apiHost = if (host.startsWith("www.")) "api." + host.removePrefix("www.") else "api." + host
    ```
  - 响应 `data.list[]`：`title / type_badge / category / year / rate / quality / detail_url / poster`。
- **详情**：`GET https://api.{host}/v1/detail?eid={eid}`；`data.resources.list[]`：`type(magnet/netdisk/...)/url/display/quality/size`。
- **eid 提取 —— 重大踩坑**：
  - 第一版正则 `Regex("/[^/]+/([A-Za-z0-9]{8,})")` 对 `https://www.foxjun.com/archives/donghua/AVqe3mmXZz.html` 误提取出 `archives` → API 404 → **详情页全空白**（用户报"狐狸君 tab 点击进入页面是空白"）。
  - 修复：直接取 URL 最后一段文件名去扩展名：
    ```kotlin
    detailUrl.substringAfterLast('/').substringBeforeLast('.')
    ```
  - 真机日志确认 `eid=AVqe3mmXZz` 正确 → 详情完整显示（标题+简介+4 资源）✅。
- **资源类型**：磁力 / 百度云盘 / 夸克云盘 / 迅雷云盘（一次全给）。
- **真机验证**：batman→32条；详情"蝙蝠侠：骑士陨落"含网盘+磁力 ✅。

### 3. 雪落影视 xlys02.com

- **ID**：`xlys` / 显示名 `雪落影视` / 适配器 `XlysAdapter.kt`
- **搜索**：`GET /search/{kw}`（SSR），**30 分钟内首次搜索必须过验证码**。
- **验证码机制（专项见文末）**：
  - 验证码页含 `<img id="verifyCode" src="/search/verifyCode?t=...">`。
  - 验证码是**算术题图片**（`12+25=?`、`51-9=?`、`90×25=?` 均实测）。
  - 用户填答案 → 直接 GET `/search/{kw}?code={答案}`（同一 JSESSIONID cookie 会话）。
  - 答错 → 返回新验证码页（**每次响应换新算式**）。
- **结果解析 —— 重大踩坑**：
  - 第一版用分类页的 `a.card-img` 选择器 → 搜索结果页**没有这个类** → 0 条（用户报"验证码输入成功但雪落搜不到"）。
  - 用 js-reverse 拿到真实结果页 HTML 才确认结构：`article.xl-result-item` → `a.xl-result-name`（标题+链接）。
  - **二次踩坑**：在 `.xl-result-item` 内 `selectFirst("a.xl-result-name, a[href*=.htm]")`，jsoup 按文档顺序命中 `a[href*=.htm]` → 选中 `.xl-result-poster`（只含 img、无标题）→ `title.isBlank()` 全 continue → 又是 0 条。
    - 日志佐证：`after submit: hasItem=true` + `parse done: itemCount=4 nameCount=4` 但 `parsed=0`（4 个元素都在却循环全跳过）。
    - 修复：**只取 `a.xl-result-name`**。本地 jsoup 测试 4/4 通过。
  - 兜底：正则 `class="xl-result-name"[^>]*href="([^"]+\.htm)"...` 防 jsoup 类名解析异常。
- **详情**：`/{cat}/{id}.htm`；表格 `table tbody tr` 每行 `td[类型] td[链接] td[备注]`，支持 magnet/ed2k/thunder/网盘。
- **✅ 当前状态**：验证码流程已恢复（v1.1.0）。`search()` 完整包含：验证码页检测 → `CaptchaFlow` 手动弹图 → 用户输入算术答案 → 同会话 `?code=` 提交 → 成功解析；答错换新图重试（最多 3 次）；用户取消该站返回空。真机验证 batman → 雪落 4 条、聚合 196 条。
- **资源类型**：磁力 / 电驴 / 网盘。
- **验证**：浏览器手工过码后（code=15 / 已种 cookie）batman→4条；App 内验证码通过后 `submit ok parsed=4`，tab `雪落影视(4)` 出现 ✅。

### 4. SeedHub seedhub.cc

- **ID**：`seedhub` / 显示名 `SeedHub` / 适配器 `SeedHubAdapter.kt`
- **搜索**：`GET /s/{kw}/`（SSR），结果 `.cover` 块内 `a[href*=/movies/]`。
- **详情**：`/movies/{id}/` → `a[href*=/link_start/]`：
  - `seed_id` → 磁力；
  - `redirect_to=pan_id` → 网盘（二维码扫码转存，App 仅展示 URL）。
- **磁力解码 —— 关键发现**：访问 `/link_start/?seed_id=...` 页面，HTML 并无磁力明文。用 js-reverse 查来源发现内联脚本：
  ```javascript
  const data = "bWFnbmV0Oj94dD11cm46YnRpaDphZTMxY...";
  window.location.href = window.atob(data);   // = magnet 链接
  ```
  `resolveSeedHubLink()` 用正则 `const\s+data\s*=\s*"([A-Za-z0-9+/=]+)"` 抠 base64 → `android.util.Base64.decode` → `String(bytes)` → 得 magnet。
- **⚠️ 限制**：搜索/详情页被 **Cloudflare 挑战**拦（`Just a moment`），App OkHttp（无 JS 执行）通常拿到挑战页。适配器检测 `Just a moment/challenge-platform` 直接返回空。首页可通但搜索/详情被拦。**保留适配器结构，站点防护关闭或换域名后可复用**。
- **资源类型**：磁力（base64 解码）/ 网盘（二维码）。
- **验证**：浏览器可搜 batman→4；App 内通常空（CF）。

### 5. 云集 binhd.com

- **ID**：`binhd` / 显示名 `云集` / 适配器 `BinhdAdapter.kt`
- **搜索**：`GET /resources/?q={kw}`（SSR）。结果 `article.resource-other-row` → `h2 a[href*="legacy-post"]`；类型取 `data-resource-kind`（movie/tv/anime/documentary）；meta 里 `#2025` 提供年份。

- **资源（csrf POST → 303 → 网盘直链）**：
  - 详情页 `article.resource-download-card`：
    - 提供商 `.resource-download-card__provider`（如"迅雷网盘"）
    - 提取码 `.resource-download-card__pill`（"提取码：2rzg"）

  - `resolveBinhdLink()`：POST 下载端点带 `csrfmiddlewaretoken` → **303 Location 直接是真实网盘 URL**（实测 `https://pan.xunlei.com/s/...?pwd=2rzg`）。
  - ResourceItem 用 `postBody="csrfmiddlewaretoken=xxx"` 存 csrf，`resolveResource()` 里还原并调用。
- **尝试**：先猜 POST body 参数、看响应 303 Location 确认无需登录（虽然有"匿名下载额度"）。
- **资源类型**：网盘（多盘，POST 跳转）。分页暂未实现（搜第 2 页 API 为空壳）。
- **真机验证**：batman→18条；详情"蝙蝠侠家族"→ 夸克网盘，解析链接成功 ✅。

### 10. 短剧狗 duanjugou.top

- **ID**：`duanjugou` / 显示名 `短剧狗` / 适配器 `DuanjugouAdapter.kt`
- **搜索**：`GET /search.php?q={kw}`（Z-BlogPHP SSR）。
- **结果解析**：`article.post-item-row` → `h2.post-title a[href*=".html"]`；标题用 `attr("title")`（内含 `<strong>` 高亮标签，需 `replace("<strong>","")` 清理）；类型 `.post-cate-badge`（短剧）。

## 验证码机制专项（雪落影视）

**开发期卡流程背景**：调其它站时验证码模态会卡住 `awaitAll()` 导致结果迟迟不显示 → 曾把验证码整段注释（雪落遇验证码返回空）以加快联调。**该问题已在 v1.1.0 恢复流程，且 v1.2.0 改为流式返回后即使雪落验证码弹窗挂着，其它站结果也已实时显示。**

**验证码完整机制（实测确认）**：
1. `GET /search/{kw}` → 若 30 分钟窗口内首次，服务端 `Set-Cookie: JSESSIONID`，页面含 `<img id=verifyCode src="/search/verifyCode?t=...">`。
2. 验证码是**算术题图片**（130×28 JPEG，实测 `14-9=?` / `55×34=?` / `65-4=?` / `12+25=?` / `51-9=?` / `90×25=?`）。
3. 用户看图算答案 → `GET /search/{kw}?code={答案}`（同一 JSESSIONID cookie）。
4. 答对 → 返回结果页（`xl-result-item`）；**答错 → 返回新验证码页，算式已换**，需重弹重答。
5. 约 30 分钟窗口内 cookie 有效，期间再搜免验证。

**尝试过的自动化方案（均弃用，最终采用户指定的"手动弹图"）**：
- macOS Vision OCR：对 130×28 小图 + 形变数字不稳定（`18+28=?` 被读成 `18-28=7`；`78-283` 误读）；放大 5 倍/8 倍后仍不稳。
- 猜测后端无答案接口（搜索过页面 JS token/captcha 无隐藏答案）。
- 结论：图片 URL 必须与提交在同一 session（cookie）；App 内实现为手动弹图 + 同会话提交。

**App 内实现要点**：
- `CaptchaFlow`（HttpEngine.kt）：`CompletableDeferred` 把请求挂起，UI 弹 Dialog，用户提交答案后 `complete`。
- `CaptchaHost`：订阅 AppViewModel 的 `captchaRequests` SharedFlow → AlertDialog（验证码图 + 输入框 + 刷新 + 取消/提交）。
- **验证码图必须用 `HttpEngine.getBytes()` 下载**（共享 cookie/UA），不能用 Coil（独立网络栈无 session）——见 App 层坑 3。
- 提交 URL：`baseUrl/search/{kEnc}?code={code}`（page=1）或 `...?page=N&code={code}`。
- 最多重试 3 次；用户取消抛 `CaptchaCancelledException` → 该站返回空。
- 超时 60 秒自动取消（避免永久阻塞聚合）。

## App 层踩坑与修复

1. **雪落解析 0 条（两次不同根因）**
   - 错用分类页选择器 `a.card-img` → 搜索结果页无此类 → 0。
   - 用 `a.xl-result-name, a[href*=.htm]` → jsoup 按文档序选中 `.xl-result-poster`（无标题）→ 全被 `title.isBlank()` 跳过 → 0。
   - 修复：`card.selectFirst("a.xl-result-name")`。

2. **狐狸君详情空白**：eid 正则误提取 `archives` → 改 `substringAfterLast('/').substringBeforeLast('.')`。

3. **验证码图不显示**：最初用 Coil `AsyncImage`（独立网络栈，无共享 cookie）→ 图片加载失败/空。改 `HttpEngine.getBytes` + `BitmapFactory.decodeByteArray` + Compose `Image`。

4. **验证码图"某方向铺满/形变"折腾记录**：
   - `fillMaxWidth()` → 横向铺满（用户不接受）；
   - `ContentScale.FillWidth` + 高度约束 → 还是横向拉满；
   - `scaleBitmap(5f)` + FillWidth → 越界且偏大；
   - `FillBounds` 固定高 130dp → 纵向拉伸形变，OCR 都读不出；
   - 用户反馈明确："原图尺寸等比放大 N 倍，宽高都×N，不做单边拉伸"。
   - 最终：`scaleBitmap(bmp, 2f)`（像素×2）+ `Modifier.fillMaxWidth(0.7f)`(宽度取容器 70%) + `aspectRatio(ratio)` 锁宽高比 + `ContentScale.Fit` → 居中、不变形、算式清晰（OCR 可读 `66×8` 等）。

5. **Tab 溢出/压缩**：`TabRow` 固定一屏，站点多时挤压。改 `ScrollableTabRow`（`edgePadding=8.dp`），可横向滑动。Cloudflare 那批站测试时 4 个 tab 正常滑动。

6. **"全部"tab 卡片还是显示来源站标签，单站 tab 内隐藏**：传 `showSite = (selected == 0)` 到 `SearchResultCard`，避免冗余。

7. **刷新验证码按钮挤变形**：底部按钮 Row 里"刷新(带图标)+取消+提交"，图标使按钮过宽挤压"提交"。去图标（仅文字"刷新"），三按钮等宽。

8. **真机自动化输入不稳定**：`adb input text` 不支持中文（NPE）、软键盘改变 tap 坐标、返回键误退桌面。验证中文站（短剧狗）改用"浏览器+jsoup JVM 测试"代替真机驱动。

9. **HttpEngine 编辑事故**：一次往 `HttpEngine.post()` 里插新方法插错位置，造成悬空 `{` + 重复定义 + 丢 `getBytes`，报一串 `Unresolved reference execute/FormBody`。修复：重排方法块、补回 `getBytes`、补 `okhttp3.FormBody` import → 编译通过。

10. **配置旧数据残留**：早期 ConfigStore 只做"补充缺失站"，不清除已删站（hkbdy 残留）。改为先 `filter { it.id in defaultIds }` 再补充缺失。

11. **`String.take(150) in string template` 与 `substringBeforeLast` 用法**：Kotlin 端正确；Java 测试脚本里误写 `String.length`（属性）→ 应为 `length()`。

12. **APP 聚合阻塞**：单站慢/验证码卡住会拖慢整体。加 `withTimeoutOrNull(20000L)` 于每个 async 站；`CaptchaFlow.ask` 加 60s 超时。
