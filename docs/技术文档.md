# SearchHub 技术文档

> 本文档面向开发者，说明 SearchHub 的技术架构、核心模块设计与关键实现细节。

## 1. 技术栈

| 层 | 选型 |
|---|---|
| 语言 | Kotlin |
| UI | Jetpack Compose + Material 3 |
| 架构 | 单 Activity + 导航 + ViewModel + 适配器模式 |
| 网络 | OkHttp 4.x + kotlinx.coroutines |
| HTML 解析 | jsoup 1.18.3 |
| 序列化 | org.json（Android 内置） |
| 构建 | AGP 9.0.1 + Gradle Wrapper 9.1.0 + Kotlin 2.3.21 |
| 兼容 | compileSdk 36 / targetSdk 36 / minSdk 26 |
| Release | R8 裁剪（isMinifyEnabled=true），APK ~1.8MB |

> 注：
> 1. AGP 9 已内置 Kotlin 支持，`build.gradle.kts` 顶层不再单独应用 `org.jetbrains.kotlin.android` 插件。
> 2. 曾使用 `kotlinx-serialization-json` / `coil-compose`，均已移除（配置改用 org.json、验证码图改用 HttpEngine+Bitmap），释放体积。

### 2.1 数据模型（data/model/Models.kt）

```kotlin
SearchResult(title, year, type, quality, rate, sourceSite, detailUrl, poster)
ResourceItem(type, title, url, fetchUrl, quality, size, sourceSite, postBody)
DetailInfo(title, originalTitle, year, rate, ..., resources, sourceSite)
CaptchaRequest / CaptchaAnswer
```

**ResourceItem.type 语义**：
- `url` 非空：最终可直接复制的链接
- `url` 空 + `fetchUrl` 非空：需二次请求换取（resolveResource）
- `postBody`：若二次请求是 POST（如 binhd csrf）

### 2.2 适配器接口

```kotlin
interface SiteAdapter {
    val id: String
    val displayName: String
    val config: SiteConfig
    suspend fun search(kw: String, page: Int = 1): List<SearchResult>
    suspend fun detail(detailUrl: String): DetailInfo
}
```

## 3. 核心模块

### 3.1 网络层 HttpEngine

统一入口，所有站点请求都经它，保证：
- 浏览器 UA（规避 403）
- 按 host 持久化 cookie（验证码 session / csrf / 下载配额）
- 可选 HTTP 代理
- 多种解码：UTF-8 / GBK（帝国CMS老站）
- 多种请求：GET / POST 表单 / POST JSON / POST 跟随 303

```kotlin
getText / getTextGbk / getBytes
postText / postTextGbk / postRaw / postJson / post
```

### 3.2 聚合 SearchRepository

```kotlin
// 一次性聚合(部分场景仍可用): 每个启用站点并发搜索，单站失败不影响他站，20s 超时兜底
suspend fun searchAll(kw, page): List<SearchResult> = coroutineScope {
    adapters.map { a -> async(IO) { withTimeoutOrNull(20000) { a.search(kw, page) } ?: emptyList() } }
        .awaitAll().flatten()
}

// 流式搜索(v1.2.0): 各站并发, 先完成先回调, UI 实时累积展示
suspend fun searchAllStream(kw, page, onBatch: (List<SearchResult>, Int) -> Unit) {
    // async 内部完成后立即 onBatch(results, doneCount), 用 AtomicInteger 计数
}

// 资源二次跳转分发（tdown→magnet / seedhub→base64 / binhd→POST→pan）
suspend fun resolveResource(item): ResourceItem
```

**流式实现要点**：
- `async(Dispatchers.IO)` 每站一个协程，协程内部完成后**立即回调** `onBatch(该站结果, 已完成站数)`（不是 `awaitAll` 等全部）
- ViewModel 累积去重（`putIfAbsent(detailUrl)`），Loading 态携带部分结果 + `done/total`，实时更新 UI
- `SearchScreen`：有部分结果即渲染 tab + 列表，顶部 `LinearProgressIndicator` 显示 `X/Y 站`；首站未到转圈

### 3.3 配置 ConfigStore + SiteConfig

- 默认站点见 `SiteDefaults.DEFAULT_SITES`
- 用户修改持久化于 `files/config.json`
- 加载时**增量合并**：保留 defaults 仍存在的站 + 自动补新站 + 过滤已移除站

### 3.4 验证码 CaptchaFlow

```kotlin
class CaptchaFlow(private val onCaptcha: suspend (CaptchaRequest) -> CaptchaAnswer) {
    suspend fun ask(req): String  // 60s 超时；取消抛 CaptchaCancelledException
}
```

- `AppViewModel` 用 `MutableSharedFlow` 发布待处理验证码
- UI `CaptchaHost` 弹出 Dialog（图片/输入/刷新/取消/提交），提交后回调 `CompletableDeferred`
- **验证码图片必须用 HttpEngine.getBytes 下载**（共享 cookie 会话），不能用 Coil
- 雪落搜索恢复验证码重试循环：手动弹图 → 用户输入算术答案 → 同会话 `?code=` 提交 → 成功解析；答错换新图重试（最多 3 次）；用户取消该站返回空

### 3.5 三处编码策略要点

| 场景 | 处理 |
|---|---|
| 帝国CMS专 POST 搜索（6v520/电影港/电影天堂/xb6v） | `postTextGbk` / `postText` |
| JSON API（451024 / Showpaw / 狐狸君） | `postJson` |
| csrf POST + 303（binhd） | `post` 返回最终 URL |

## 4. 关键实现细节与已知坑

详见 [docs/站点对接文档.md](docs/站点对接文档.md) 的逐站记录，此处仅列最重要的 5 条：

1. **雪落 `xl-result-name` 选择器**：不要并列 `a[href*=.htm]`，jsoup 会误选中只含图片的 `.xl-result-poster`（无标题）导致 0 条。
2. **狐狸君 eid**：`substringAfterLast('/').substringBeforeLast('.')`，别用正则。
3. **xb6v 搜索**：必须是 `/e/search/11index.php` + `catid=0`，否则返回"没有搜索到相关的内容"。
4. **binhd 资源**：POST 下载端点（csrf）→ 303 Location 即真实网盘 URL。
5. **SeedHub / hkbdy**：被 Cloudflare 挑战拦截，App OkHttp 无法过纯 JS 挑战，实际返回空。
6. **APK 体积优化**：`material-icons-extended` 有 11105 个图标类（单个 classes.jar 36MB），必须开 R8（`isMinifyEnabled=true`）自动裁掉未用图标；再移除死依赖（coil、kotlinx-serialization-json），13MB→1.8MB。
